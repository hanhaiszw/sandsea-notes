## 1. 安装与构建

### 环境要求

- **Node.js 20.19+ 或 22.12+**（Vite 7 的要求）
- macOS 为当前开发与验证平台；代码按跨平台约束编写，但 Windows / Linux 未经测试

### 从源码运行

```bash
npm install
npm run dev
```

国内网络建议给 Electron 二进制走镜像：

```bash
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm install
```

npm 11 默认会拦截依赖的 install 脚本，若 Electron 二进制没下载成功，补跑一次：

```bash
node node_modules/electron/install.js
```

### 全部命令

```bash
npm run dev         # 开发模式，带热更新
npm run typecheck   # 类型检查（主进程 + 渲染进程）
npm run build       # 类型检查 + 构建到 out/
npm start           # 以构建产物启动（需先执行 npm run build）
npm run pack        # 构建并打包成 release/mac-arm64/Sandsea Notes.app
npm run icon        # 改过 build/icon.svg 后重新生成图标
```

### 打包成 .app（macOS）

`npm run pack` → 产物在 `release/mac-arm64/Sandsea Notes.app`，拖进「应用程序」即可双击使用，不需要终端。

> - 改过名字（`build.productName`、`appId`）后重新打包，Dock 里可能还留着旧名字/旧图标——那是 LaunchServices 的缓存，把旧图标从 Dock 移除再拖一次新的即可。
> - **安装时要拖整个 `.app`**（`release/mac-arm64/Sandsea Notes.app` 这个「文件夹」本身）到「应用程序」，**不要**拖 `Sandsea Notes.app/Contents/MacOS/Sandsea Notes` —— 那是包内部的可执行文件，单独拖出来是个「文稿」，双击会被 TextEdit 打开并报「文本编码 Unicode（UTF-8）不适用 / 可能不是文本文件」。在 IDE 文件树里 `.app` 会显示成普通文件夹，很容易一路点进去，注意别点错。Finder 默认隐藏扩展名，包内外两个东西都显示为「Sandsea Notes」，认图标是应用图标的那一个。
> - `build.electronDist` 指向 `node_modules/electron/dist`，让 electron-builder **直接用本地已装好的 Electron，不去 GitHub 下载**。这条请勿删除：本机到 GitHub 的连接会卡住（实测 TCP 停在 `SYN_SENT`），删掉后打包会一直挂在那里不动。
> - **未做代码签名**。自己机器上用没问题——本地构建的文件没有隔离属性，Gatekeeper 不拦，双击可正常启动（已实测）。发给别人则会被拦，那需要 Apple 开发者账号做签名 + 公证。
> - 只打当前架构（本机为 arm64）。要给 Intel Mac 用需另外配置 `universal` 目标。
> - 打包版与 `npm run dev` **共用同一份配置和笔记库**（都在 `~/Library/Application Support/Notes`），来回切换不会丢设置，但**不要同时开**（同一个 profile 会被两个进程争用）。

### 应用图标

矢量源文件是 `build/icon.svg`，改完执行 `npm run icon` 重新生成：

- `build/icon.png`（1024×1024，开发时设 macOS Dock 图标用）
- `build/icon.icns`（打包用）

生成脚本用 Electron 自带的 Chromium 光栅化，每个尺寸都直接从矢量渲染，因此不需要额外安装任何图像工具。

### 关于端口

**端口只有开发模式才用。** `npm run dev` 会起一个 Vite 开发服务器（默认 5173），供 Electron 加载界面；这个端口被占用时 Vite 会自动顺延到 5174、5175…… 并把实际端口告诉 Electron，不需要手工处理。

**构建产物（`npm start` 或打包后的应用）不监听任何端口** —— 界面直接从磁盘上的 `out/renderer/index.html` 加载，所以装到别的电脑上不存在端口冲突问题。

## 2. 选择笔记库

首次打开是欢迎页，点 **「用这个位置开始」** 用默认位置建库，或点 **「选择其他文件夹」** 自己挑一个。

- 左侧会列出该文件夹里的 Markdown 文件与附件
- 打开时会自动为这个文件夹开启本地版本历史（见第 5 节）
- 点侧栏的 **「更换文件夹」** 可随时换库（不会动原文件夹里的任何内容）
- 隐藏目录、`node_modules`、`.git` 等不会被显示

## 3. 新建与编辑

### 新建

在文件树上**右键** → 「新建笔记」/「新建文件夹」。创建位置由右键的位置决定：

- 右键**文件夹** → 建在该文件夹里
- 右键**文件** → 建在该文件所在目录
- 右键**空白处** → 建在笔记库根目录

弹窗顶部会写明创建位置；新建笔记不需要填扩展名，会自动补 `.md`；创建后自动打开。

右键菜单按 `Esc`、点击菜单外、滚动或缩放窗口都会收起。

### 保存

**保存是自动的**：停止输入约 0.7 秒后落盘，`Cmd+S` 可立即保存。编辑区右上角会显示 `已保存` / `未保存` / `保存中…`（当前打开的是哪个文件，看左侧文件树里高亮的那一行）。

### 右键菜单

在编辑区里**选中文字后右键**，可以剪切 / 复制 / 粘贴 / 全选；没有选中文字时「剪切 / 复制」是灰的。剪贴板读写由主进程完成，不依赖渲染进程的剪贴板权限。

### 格式工具栏

编辑区上方一排按钮，选中文字后点击即可套用格式；没选中文字时会插入占位内容并选中它，直接输入就能替换。

| 分组 | 按钮 |
|---|---|
| 行内 | 加粗 `B`、斜体 `I`、删除线 `S`、行内代码 `<>`、链接、文字颜色 |
| 标题 | `H1` `H2` `H3` |
| 列表 | 无序 `•`、有序 `1.`、待办 `☐`、引用 `❝` |
| 插入 | 代码块、表格、Mermaid 图表、分隔线 |

**表格**：点表格按钮会展开一个方格盘，鼠标划到哪格、面板上就显示几列几行（最多 10 × 10），点一下即插入；点面板外或按 `Esc` 取消。行数含表头行 —— 选「3 行」得到的是 1 行表头 + 2 行正文，渲染出来正好 3 行。

**文字颜色**：点 `A` 带色条那个按钮会展开 8 个预设色，另外有系统取色器可选任意颜色，还有「清除颜色」。选中文字后点颜色即可上色；**对已经上色的文字再点别的颜色是换色，不会层层嵌套**。

> 颜色存成 `[文字]{color=#c2635a}`。Markdown 没有原生的文字颜色语法，写成 `<span style="color:...">` 就得把渲染器的原始 HTML 透传打开，粘贴外部内容时会多一条 XSS 攻击面，所以这里沿用了图片 `{width=320}` 的同一套花括号属性写法。支持十六进制色值，以及 `red` / `orange` / `yellow` / `green` / `teal` / `blue` / `purple` / `pink` / `gray` / `black` / `white` 这些颜色名；认不出来的值会原样显示成文本，不会再往 `style` 里塞东西。

标题、列表、待办、引用是**开关式**的：对已经是该格式的行再点一次会取消；从一种行级格式切换到另一种（比如引用行改列表）是替换而不是叠加，行首缩进会保留。表格、代码块、Mermaid 会插入一段可直接修改的模板。

### 插入图片

截图后直接 `Cmd+V`，或把图片文件拖进编辑区，会自动：

1. 存到**笔记库根目录**的 `images/`（按需创建），文件名形如 `image-20260929-234654.jpg`
2. 在光标处插入引用，例如 `![名字](images/image-20260929-234654.jpg)`

引用路径会按笔记所在层级自动换算——笔记在子目录里就写成 `../images/xxx.png`。所以整个笔记库搬到别处不会失效；但把单篇笔记挪到不同层级时，需要自己调整这个前缀。支持 `png / jpg / jpeg / gif / webp / svg`，单张上限 20 MB。

预览里的图片不是直接读磁盘，而是走一个只放行「笔记库内图片」的内部协议（见[数据与安全](#7-数据与安全)）。

### 调整图片大小

鼠标移到预览里的图片上，右下角会出现一个手柄，拖动即可改宽度；松手后宽度写回源码：

```markdown
![图](images/x.png){width=320}
```

也可以自己在源码里写这个花括号（支持 `width` / `height`，单位像素），预览就按这个尺寸显示。改动会进入撤销历史，`Cmd+Z` / `Ctrl+Z` 可以撤回。

> 引用式写法（`![描述][引用]`）暂不支持拖拽调整——编辑器语法树里拿不到它的地址，无法确认改的是同一张图。拖动时会在底栏提示。

### 查看图片

点击文件树里的图片文件，右侧会按可用空间等比缩放居中显示（标题栏显示 `图片`，没有编辑/分栏/阅读切换）。图片只读，不需要保存；切回笔记时会自动恢复编辑。

## 4. 视图与主题

内容区右上角三个按钮切换视图：

| 视图 | 说明 |
|---|---|
| 编辑 | 只看源码 |
| 分栏 | 左边源码、右边实时预览 |
| 阅读 | 只看渲染结果 |

**分栏时两边的滚动是联动的**，而且只保留一条滚动条（右侧预览那条），滚任意一边另一边都会跟上。对齐的基准是**源码行号**而不是滚动百分比 —— 编辑器行高固定，预览里却有图片、表格、图表，两边内容高度差得远，按比例对齐一旦遇上大图或长代码块就会错位，而且越滚越偏。

预览支持 GFM 表格、任务列表 `- [ ]`、脚注、代码块等。**Mermaid 图表**（` ```mermaid ` 代码块）会渲染成真正的流程图 / 时序图，并按当前主题配色；源码写错时会在原位显示错误信息和原始代码，不会让整篇预览崩掉。

### 在预览里直接改

分栏和阅读视图里的预览不只是看的：待办项和表格可以直接动手改，改完自动写回源码并保存。

- **勾选待办** —— 直接点 `- [ ]` 前面的复选框，源码里的 `[ ]` 跟着变成 `[x]`，再点一次改回来。点文字不会触发勾选，方便选中待办文字复制。
- **改表格内容** —— 点进任意单元格（表头也能改）直接输入，**停手约 0.4 秒**内容就写回源码，不用离开表格；按回车或点到表格外会立刻写回。光标在格子里时**方向键能在格子之间走**：左右键走到一格的头部 / 尾部再按一下就跳进相邻的格子，上下键跳到上 / 下一行的同一列；按住 `Shift` 仍是普通的扩选。
- **增删行列** —— **在单元格上按右键**，菜单里有「上方插入行 / 下方插入行 / 删除本行 / 左侧插入列 / 右侧插入列 / 删除本列」，都**以按右键的那一格为基准**。表头行删不掉、最后一列也删不掉，这两项会置灰。菜单下半部分是「剪切 / 复制 / 粘贴」，右键前选中的文字会一起带过来。在表格**以外**的地方按右键仍是浏览器自带的菜单，复制、查询照旧。

这些改动都会进入撤销历史，`Cmd+Z` / `Ctrl+Z` 可以撤回。两点需要知道：

- 单元格按**纯文本**写回：动过的那一格，原有的加粗、链接、行内代码会被替换成纯文本；没动过的格子不受影响。要保留格式就回源码里改。
- 单元格内容里的 `|` 会自动写成 `\|`，否则表格会被切断。

> 写回会让预览重渲染、把这一格的 DOM 整个换掉，所以实现里会把光标连同格内位置一起补回去 —— 停在格子里不动也能看着左边源码跟着变。用输入法打字时则等**组完字**再写，否则候选词会被打断。

状态栏里的 **`跟随系统` / `白天` / `黑夜`** 按钮点击即可循环切换主题，选择会被记住。默认「跟随系统」。

状态栏右侧的 **「关于」** 里有软件简介、版本号，以及 Markdown 语法参考的链接（点击交给系统浏览器打开，应用本身不加载远程内容）。

### 快捷键

| 快捷键 | 作用 |
|---|---|
| `Cmd+S` / `Ctrl+S` | 立即保存 |
| `Cmd+B` / `Ctrl+B` | 加粗选中内容 |
| `Cmd+I` / `Ctrl+I` | 斜体选中内容 |
| `Tab` | 缩进当前行（有选区时缩进所有选中行） |
| `Shift+Tab` | 取消缩进 |

> 其余依赖编辑器内置行为（撤销、查找、列表续行、粘贴时自动补链接等）。
> 想用 `Tab` 在界面控件之间切换，按 `Esc` 可临时恢复 Tab 的焦点跳转。

## 5. 版本历史与同步

底栏点 **「设置」**。弹窗分两块，本地在前、远程在后。

### 本地版本历史（默认就有）

打开一个文件夹当笔记库时，本地版本历史会**自动开好**，不需要任何配置。历史记在笔记库目录的 `.git` 里，全程在本机、不联网。

这一块唯一要确认的是 **提交署名**（姓名 + 邮箱）：它写进每一次提交的记录，默认取系统用户名和 `用户名@localhost`，可以改成你常用的邮箱（推送到 GitHub / Gitee 时对方会看到这一项）。

### 推送到远程（可选，默认收起）

想让另一台设备也看到这些笔记时，展开这一块填写：

| 字段 | 说明 |
|---|---|
| 远程地址 | 例如 `https://gitee.com/用户名/仓库.git`，或 GitHub 的 HTTPS 地址 |
| 账号名 | Gitee 需填真实账号名；GitHub 可填任意非空值 |
| 访问令牌 | Gitee 用「私人令牌」，GitHub 用 Fine-grained PAT。**留空表示不修改已保存的令牌** |
| 分支 · 实现方式 | 收在「高级」里，一般不用动。内置实现无需安装 git，仅支持 HTTPS；系统 git 支持 SSH |

填完地址点 **「保存」** 即可，不需要再点别的按钮 —— 底栏的按钮会从「提交到历史」变成「同步」。

> 仓库要先去 GitHub / Gitee 上建好，建议建成空仓库（别勾 README），否则第一次同步会提示远端领先。
> 令牌只在保存时输入一次，之后由系统钥匙串加密保存，不会写进笔记目录。
> 远程上已经有这个笔记库的仓库？用同一块底部的 **「从远程克隆」**，克隆到本地并自动切换过去。

## 6. 日常提交与查看历史

底栏会常驻显示状态，例如 `未提交 3 个文件的改动`。点 **「提交到历史」**（配了远程地址后变成「同步」）：

1. 弹窗**左边列出这次要提交的改动文件**，每个后面标着 `+N` `−M`；**点一个文件，右边就显示它的逐行改动**（`+` 新增行、`−` 删除行）。打开时会先自动选中第一个，不用先点一下才知道右边能看什么
2. 提交信息默认填当前时间（形如 `2026-10-02 22:30`），可以改成你想写的
3. **只有本地历史**：点「提交到历史」写入本地版本历史
4. **配了远程**：多一个「提交并推送」，也可以先「仅提交到本地」

> 图片之类的二进制文件不做行级对比，展开时只会说明一句，提交后整份记进历史。

| 底栏状态 | 含义 |
|---|---|
| 本地版本历史还没开启 | 自动开启失败，点「设置」→「立即开启」 |
| 本地仓库，暂无待提交的改动 | 工作区干净 |
| 未提交 N 个文件的改动 | 有改动可以记一版 |
| 已接入仓库，还需要填写访问令牌 | 填令牌（仅 HTTPS 远程需要） |
| 没有需要同步的改动 | 工作区干净 |
| 未同步 N 个文件的改动 | 有改动待同步 |

**两台机器都改过、历史分叉时**：同步会提示远端领先，底栏出现 **「拉取」** 和 **「打开笔记库文件夹」**。先用「仅提交到本地」把这边的内容存进版本历史，再拉取；如果两侧改到了同一个文件，应用不自动合并，需要在笔记库目录里手工处理。

### 查看历史与恢复文件

笔记库只要是个 Git 仓库（配没配远程都算），底栏就会出现 **「历史」** 按钮。面板横向铺开三栏——**提交记录 | 改动文件 | 差异**，三栏都常驻，点哪一栏右边就跟着换，不需要「返回上一级」：

1. 左栏是提交记录，点一条 → 中栏列出这次改动的文件，每个文件后面标着 `+N` `−M`
2. 点中栏的文件 → 右栏展开它的逐行差异，`+` 是新增行，`−` 是删除行
3. 想退回某一版，点右栏上方的 **「恢复成这一版」**

打开时已经自动选中最新一条提交、以及它改动的第一个文件，所以三栏一开就有内容。

> 列比较窄，提交信息和文件路径太长时会被省略号截断 —— **鼠标停在那一行上就会浮出完整文字**。
> 图片之类的二进制文件不做行级对比，文件行上不会显示行数。

恢复是**文件级**的：只把这一个文件的内容改回那次提交时的样子，别的文件不受影响，分支指针也不会移动。恢复出来的内容算作一个「待提交的改动」，不会自动提交 —— 你可以先在编辑器里看一眼，再决定要不要提交。

> 若那个文件正在编辑器里且有未保存的改动，恢复会被拦下。先保存或撤销，再恢复。

## 7. 数据与安全

| 内容 | 位置 |
|---|---|
| 笔记 | 你选择的笔记库文件夹（纯 Markdown，无附加元数据） |
| 粘贴的图片 | 笔记库根目录的 `images/`（普通图片文件，随笔记一起同步） |
| 版本历史 | 笔记库目录下的 `.git`（标准 Git 仓库，不联网也能用；换库不会带走它） |
| 应用配置 | `~/Library/Application Support/Notes/config.json` |
| Git 访问令牌 | `~/Library/Application Support/Notes/credentials.json`（经 `safeStorage` 加密，文件权限 `600`） |

几点设计约束：

- **令牌不写入笔记目录、不进日志**；传给 git 时走环境变量，不出现在命令行参数里
- **图片走内部协议加载**（`notes-asset://`）。渲染进程只能请求这个协议，主进程逐个校验路径：必须是笔记库内的文件、且扩展名在图片白名单里，越界与其它文件类型一律返回 404。之所以不用 `file://`，是因为那等于把整个文件系统的读权限交给页面
- **粘贴/拖入的图片只传二进制内容给主进程**，渲染进程无法指定任何读写路径
- **绝不静默覆盖**：写回前比对文件修改时间，检测到外部改动就拒绝写入并提示
- **不做有损 Git 操作**：不自动 `rebase`、不 `force push`，远端领先时只提示
- 界面不发起任何外部网络请求（除你配置的 Git 远程外无遥测）；字体与主题全部本地，不引远程资源

**重置应用配置**：退出应用后删除 `config.json`（笔记本身不受影响）。

## 8. 常见问题

**每次打开都弹 macOS 钥匙串/密码提示**
窗口使用内存会话，Chromium 不会再为 cookies 去访问钥匙串。若仍出现，请把弹窗原文记录下来——那说明来源不是钥匙串，需要另行定位。

**打开了但没有配色/看着是白天主题**
主题默认「跟随系统」。系统是浅色时就是白天主题，点状态栏的主题按钮切到「黑夜」。

**`Port 5173 is in use`**
上一次的 dev 进程没有退干净。**不需要处理**：Vite 会自动换到 5174 并继续启动，只是终端里会多一行提示。想找回 5173 就关掉旧终端或结束残留的 `node` / `Electron` 进程后重试。

**粘贴的图片在预览里显示不出来**
依次排查：图片扩展名是否在白名单内（`bmp`、`heic` 等不支持）；引用路径是否被手工改过或图片被移动（图片固定在笔记库根目录的 `images/`，子目录里的笔记需要 `../images/...` 前缀）；图片是否还在笔记库内（预览只放行笔记库内的图片）。

**同步提示「远端有本地没有的提交」**
远端比本地新，先点「拉取」。若本地也有未提交改动，先用「仅提交到本地」。

**同步提示「文件已被外部修改，为避免覆盖对方的改动，本次保存已取消」**
文件在编辑期间被其他程序改过。为避免丢掉那边的改动，应用拒绝写入——可以在编辑器里复制内容，重开文件后再粘贴。

## 10. 技术栈与项目结构

Electron + React + TypeScript + Vite；编辑器 CodeMirror 6；渲染 markdown-it；Git 为 isomorphic-git（内置）/ simple-git（系统）；配置 electron-store；凭证 safeStorage。

```
src/
├── shared/      主/渲染进程共用：IPC 契约、领域模型、主题、跨平台工具
├── main/        主进程：窗口与安全基线、IPC 路由、笔记库/监听/索引、Git 服务
├── preload/     contextBridge 白名单桥（不暴露通用 invoke）
└── renderer/    React 界面：文件树、编辑器、预览、Git 面板、状态栏
```

架构与决策细节见 [技术方案.md](../技术方案.md)（中文）。

## 11. 参与贡献

欢迎提 Issue 和 PR。提交前请确认：

1. **`npm run typecheck` 通过** —— 主进程与渲染进程都做了严格类型检查，类型错误会直接挡住合并
2. **改动尽量小而聚焦** —— 一个 PR 解决一个问题，方便 review
3. **注释与 UI 文案用中文** —— 与现有代码保持一致
4. **提交信息说明「为什么」** —— 「做了什么」看 diff 就够了

### 架构边界（改动前请先了解）

| 层 | 职责 | 约束 |
|---|---|---|
| `src/main/` | 窗口、IPC 路由、文件系统、Git | 唯一持有特权的一层 |
| `src/preload/` | contextBridge 白名单桥 | **只暴露具体方法，不暴露通用 `invoke`** |
| `src/renderer/` | React 界面 | 沙箱内运行，只能经 `window.notes` 访问系统能力 |
| `src/shared/` | IPC 契约、领域模型、主题 | 主/渲染进程共用，不得引入 Node 或 DOM API |

安全基线（`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`）是**硬约束**，不接受为了开发方便而放宽的改动。
